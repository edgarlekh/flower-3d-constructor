> Этот документ — бриф для реализации. Читать вместе с `docs/architecture.md` и памятью проекта.

## 0. TL;DR (что делать в первую очередь)
Референс — это **единый 2D-план ↔ 3D** планировщик банкетного зала с реальными размерами,
библиотекой мебели/декора и **фотореалистичным 3D для показа клиенту**. У нас архитектура
такая же (plan.html ↔ hall.html на общем `localStorage.flowerHall`), но не хватает трёх вещей:
1. **Контур/стены зала с реальными размерами** (сейчас нет — столы стоят «в воздухе»).
2. **Объекты зала (сцена/арка/танцпол/бар) в 3D** (сейчас рисуются только в 2D-плане).
3. **Качественный 3D для «вау»** — модели стульев/столов, материалы (скатерть/дерево),
   декор (драпированная арка, задник-фотозона, подиум). Это главный товар декоратора.

## 1. Что это за приложение (по видео)
- **Класс:** профессиональный 3D-планировщик интерьера/мероприятия (уровень Live Home 3D /
  Planner 5D). iPad + Apple Pencil.
- **Единая модель, два вида:** мгновенное переключение вид сверху (2D-план с линейками) ↔ 3D
  перспектива того же зала. Это ровно наша концепция.
- **Реальные размеры везде:** линейки по краям канваса в футах/дюймах, размер зала
  `117'0" × 50'7"`, столы подписаны `72"` (круглый ⌀72″), `8'×4'`, `8'×42"`.
- **Панель свойств объекта:** `Width / Depth / Height / Elevation / Angle` + счётчик
  `Triangles` (значит под капотом настоящий 3D-меш, растёт по мере добавления).
- **Богатая библиотека:** круглые/банкетные столы, детальные стулья (модели, не коробки),
  лаунж-диваны «П», сервировка/тарелки на столе, **арка-портал со шторами**, **задник
  (ботаническая фотозона)**, **статуи**, **подиум/сцена**, растения.
- **Сборка рядов:** длинный президиум собран из трёх `8'×4'` встык, стулья по всей длине.
- **3D-качество:** реалистичные материалы (дерево, ткань, обивка), драпировки, свет — картинка
  «для показа заказчику».

## 3. Что у НАС уже сильно (не потерять при доработке)
- **Конструктор букета** — уникальная флористическая фишка, которой у референса нет вообще.
  Наш продукт = «декор + флористика», а не просто расстановка мебели. Это дифференциатор.
- **Стулья-слоты с «дырками»** (убрать конкретный стул, соседи не двигаются) + торцы.
- **Аналитика для декоратора:** зазоры **между стульями** соседних столов (красным если тесно),
  проход между столами, суммарный счётчик гостей у сдвинутых столов, привязка/направляющие,
  всё в реальных см. У референса из видео такой «умной» аналитики не видно.
- **Готовые схемы** (буква П, президиум, ряды, сетка), выверенные численно.
- **Общие данные plan↔hall**, кликабельная схема стола, редактирование букета прямо в зале.

Вывод: догонять референс надо в **контуре зала**, **декоре/объектах в 3D** и **качестве 3D**,
не жертвуя нашими сильными сторонами (букеты + аналитика рассадки).

## 4. Приоритетный план внедрения (по влиянию на декоратора)

### P0 — Ядро, «догнать план как инструмент» (делать первым)
- **4.1 Контур зала со стенами и размерами.** В plan.html: инструмент «Зал/помещение» —
  прямоугольник (или ломаная) с вводом ширины/длины в метрах, вход/двери, отрисовка стен.
  Столы внутри; **fit-check** — предупреждать, если стол вылезает за стены. Хранить в
  `localStorage.flowerRoom` (расширить схему: добавить `walls`/`bounds`), чтобы 3D тоже знал габариты.
- **4.2 Объекты зала В 3D.** Сейчас `flowerRoom` (танцпол/сцена/бар/арка) рисуется только в
  плане. В hall.html читать `flowerRoom` и строить простые 3D-примитивы: танцпол — плоскость с
  паркетом; сцена/подиум — приподнятый бокс; бар — стойка; арка — две стойки + перекладина.
  Даже грубо — это резко повышает ценность 3D-показа.
- **4.3 Кастомные размеры стола.** В инспекторе plan.html дать ввод длины/ширины (см) и диаметра,
  а не только 3 пресета. Пересобирать слоты стульев под новый размер.

### P1 — «Вау для клиента» (3D-качество и декор)
- **5.1 Лучше 3D-мебель/материалы в hall.html:** стул — узнаваемая форма (спинка+ножки уже есть,
  добавить материалы/цвет обивки), стол — дерево/скатерть с мягким бликом (мы уже начали
  glass/тени в 2D — перенести идею в 3D материалы). Скатерть уже есть — усилить.
- **5.2 Декор в 3D:** арка с драпировкой (две стойки + ткань), задник/фотозона (плоскость с
  текстурой/цветом), подиум/сцена, растения/зелень у арки. Библиотека, как объекты зала, но с 3D.
- **5.3 Elevation (высота):** параметр высоты для декора — арка/подвесные композиции/подиум над
  полом. В `flowerRoom`-объект добавить `y`/`h`.

### P2 — Глубина рабочего процесса
- **6.1 Рассадка гостей + импорт списка** (уже в нашем плане): вставить имена → перетащить на стул,
  имя на месте, счётчик «рассажено N из M», хранить в `flowerHall` (совместимо с 3D-рассадкой).
- **6.2 Экспорт/печать:** PDF плана сверху + схема рассадки (для зала/официантов/клиента). Скил `pdf`.
- **6.3 Линейки по краям канваса** в plan.html (в дополнение к сетке) — как в референсе.
- **6.4 Библиотека столов-размеров** шире (72″/60″ круглые, 6ft/8ft банкетные) — под реальные каталоги.

## 5. Готовые тикеты для Claude Code (можно брать по одному)

**T1 — Контур зала (P0).** plan.html: инструмент «Помещение»: задать размеры зала (ширина×длина, м),
отрисовать стены/контур, показать площадь; столы за стеной подсвечивать красным (fit-check).
Хранить габариты в `flowerRoom` (или новый ключ `flowerVenue`). Проверить Playwright'ом.

**T2 — Объекты зала в 3D (P0).** hall.html: на старте читать `flowerRoom` и строить 3D-примитивы
для kind ∈ {floor(танцпол), stage(подиум), bar, arch}. Позиции/размеры/поворот в см из плана.
Материалы простые, но узнаваемые. Синхронно с планом (общие данные).

**T3 — Кастомный размер стола (P0).** Инспектор plan.html: поля длина/ширина (банкет) и диаметр
(круглый) в см; перестроение слотов стульев. Совместимо с `flowerHall` (hl/hw/R уже есть).

**T4 — 3D-декор арка+задник (P1).** hall.html: арка (2 стойки + драпировка-плоскость) и задник-
фотозона как объекты зала; параметр высоты. Цель — красивый кадр для показа клиента (см. видео).

**T5 — Улучшить 3D-стул/стол материалы (P1).** hall.html: обивка стула, дерево/скатерть стола,
мягкие блики — приблизить к фотореалистичности из референса. Задействовать `frontend-design`/`ui-ux-pro-max`.

**T6 — Рассадка гостей + импорт (P2).** plan.html: список имён (вставка/по одному), перетаскивание
на стул, имя на месте, счётчик «рассажено N из M», хранить в `flowerHall`.

**T7 — Экспорт PDF (P2).** plan.html + рассадка → PDF (план сверху + список рассадки). Скил `pdf`.

## 6. Как проверять (важно)
- **Геометрию/размеры — кодом** через `window.hallDebug` (`tableGap`, `tableExtent`,
  `computeWarnings`) до показа; целевой комфортный проход ≥ 85 см (см. память проекта).
- **Внешний вид — Playwright** (открыть страницу, скриншот, сравнить), затем `/code-review`,
  потом коммит и пуш.
- **Общие данные plan↔hall** проверять round-trip: изменил в плане → открыл 3D → всё на месте,
  bouquets/settings/gaps сохранены.
