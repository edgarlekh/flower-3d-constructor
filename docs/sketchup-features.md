# SketchUp: что в нём есть и что нужно нам (выжимка + адаптация)

> Пользователь сам работает в SketchUp для декора. Здесь — разбор возможностей SketchUp,
> релевантных декоратору свадеб/мероприятий, и что из этого адаптировать в наш продукт
> (flower-3d-constructor: `constructor.html` + `plan.html` 2D-план + `hall.html` 3D-зал).
> Философия: мы НЕ становимся SketchUp (это тяжёлый 3D-редактор). Мы берём только
> декоратор-полезные вещи и делаем их **простыми в вебе**, сохраняя нашу фишку — букеты + аналитику.

## 0. Главная мысль
Сила SketchUp для декоратора — **не моделирование, а готовая библиотека декора (3D Warehouse)
+ реальные размеры + простой показ клиенту**. Именно это надо перенести. Наше преимущество:
мы легче (браузер, ничего не ставить), заточены под флористику (конструктор букета) и даём
**умную аналитику рассадки**, которой в SketchUp нет из коробки.

## 1. Возможности SketchUp → зачем декоратору → наш статус → что делать

| SketchUp | Зачем декоратору | У нас сейчас | Что взять (адаптация) |
|---|---|---|---|
| **3D Warehouse** — огромная библиотека готовых моделей (столы, стулья chiavari, **арки, сцены с цветами, драпировки, танцполы, лаунж, инсталляции**) | Не моделировать с нуля — вставил готовое | 4 объекта в 2D-плане (танцпол/сцена/бар/арка), простые примитивы | 🔑 **Ключевое.** Расширить **библиотеку готового декора** (пресеты) и рисовать её и в 2D, и в 3D: арка, сцена/подиум, задник-фотозона, танцпол, лаунж-зона, цветочные инсталляции |
| **Tape Measure + Dimensions + Guides** — мерить, ставить размеры, направляющие | Точная посадка по реальным размерам | Реальные см, метрическая сетка, зазоры стул-к-стулу | Добавить: **линейки по краям**, произвольные размеры объектов (ввод см), тянущиеся направляющие-гайды |
| **Inference (умные привязки)** — подсказки выравнивания к точкам/осям/центрам | Ровно выровнять столы/ряды | Привязка + розовые направляющие в плане (частично) | Усилить: привязка к центрам/краям/сетке, «примагничивание» рядов |
| **Components** — переиспользуемый объект: правишь один → меняются все копии | Массово править типовые столы/сервировку | Копия стола/букета (независимые) | Идея **«тип стола»**: изменил шаблон (размер/стулья) → применилось ко всем столам этого типа |
| **Materials / Textures** — дерево, ткань, **скатерть**, паркет, драпировки | Реализм для показа клиенту | Только цвет скатерти | Добавить материалы: скатерть/дерево стола, обивка стула, паркет танцпола, ткань драпировки — для «вау» в 3D |
| **Scenes (сохранённые ракурсы) + Walkthrough/анимация** | Красивые виды для презентации + пройтись | **Прогулка (walk mode) уже есть** | Добавить **сохранённые ракурсы**: «общий вид», «на президиум», «от входа» — переключение одной кнопкой для показа клиенту |
| **Shadows / Sun (солнце по времени)** | Атмосфера, реалистичный свет | Мягкие тени есть (PCFSoftShadowMap) | Опционально: пресеты освещения (день/вечер/тёплый) для настроения |
| **LayOut** — 2D-чертежи/планы из модели, для печати | Отдать план залу/официантам/клиенту | `plan.html` = вид сверху (есть) | Добавить **экспорт/печать PDF** плана + схемы рассадки (наш «LayOut», скил `pdf`) |
| **Tags / Layers (слои)** — вкл/выкл группы объектов | Показать только мебель / только декор / со стенами | Нет | Переключатели слоёв: столы / декор / стены / рассадка / размеры |
| **Push/Pull + рисование** — произвольная геометрия (нестандартный зал, подиум) | Нарисовать реальную форму зала | Только прямоугольные пресеты | **Контур зала ломаной** (нестандартные помещения) + высота подиума |
| **Export (картинки/2D/3D)** | Картинка для клиента, файл | Ссылка-показ (view-only) | Добавить экспорт картинки (Playwright/canvas) + PDF |

## 2. Выжимка: ТОП того, что реально нужно взять (по приоритету)

**P0 — фундамент и «догнать инструмент»**
1. **Библиотека декора (пресеты) в 2D+3D** — арка, сцена/подиум, задник-фотозона, танцпол, бар,
   лаунж. Сейчас есть только в 2D-плане → **рендерить в 3D-зале** (читать `flowerRoom`).
2. **Контур/стены зала с размерами** — реальное помещение, fit-check (стол за стеной = красный).
3. **Произвольные размеры стола** (ввод см), а не только пресеты.

**P1 — «вау» для показа клиенту (это и есть товар декоратора)**
4. **Материалы в 3D** — скатерть/дерево стола, обивка стула, паркет, драпировка арки.
5. **Готовые 3D-декорации** — арка с тканью, задник-фотозона, цветочные инсталляции у арки.
6. **Сохранённые ракурсы (scenes)** — кнопки «общий / президиум / вход» + уже готовая прогулка.

**P2 — рабочий процесс**
7. **Рассадка гостей + импорт списка** (в плане).
8. **Экспорт/печать PDF** (план + рассадка) — наш аналог LayOut.
9. **Слои** (вкл/выкл: мебель / декор / стены / размеры).
10. **Линейки по краям** канваса.

## 3. Чего НЕ надо тащить из SketchUp (чтобы не утяжелить)
- Полноценное 3D-моделирование (push/pull произвольных мешей), булевы операции, компоненты-скрипты —
  это CAD, нашему пользователю (не-инженеру) не нужно и отпугнёт.
- Загрузку тяжёлых `.skp`/3D Warehouse-моделей в браузер — вместо этого свои лёгкие пресеты-примитивы.
- Сам «редактор геометрии» — у нас расстановка готовых объектов, а не черчение с нуля.

Мы остаёмся **простыми**: выбрал готовое → поставил → покрасил → показал. Это и ценят декораторы
(из видео и обзоров: «интуитивно, быстро набросать план»).

## 4. Как это ложится на наши файлы
- **Библиотека декора / объекты:** `plan.html` (2D) уже пишет `localStorage.flowerRoom`;
  `hall.html` (3D) должен это читать и строить примитивы → см. тикет **T2** в `reference-analysis.md`.
- **Стены зала:** расширить `flowerRoom`/новый `flowerVenue`; 2D-контур + 3D-стены. (тикет **T1**)
- **Материалы/декор в 3D:** новые THREE-примитивы + материалы в `hall.html`. (тикеты **T4/T5**)
- **Сохранённые ракурсы:** сохранять положение камеры (у нас `camera-controls.js`).
- **Экспорт PDF:** скил `pdf` + `plan.html`/рассадка. (тикет **T7**)

## 5. Итог
SketchUp даёт декоратору: **готовый декор + размеры + красивый показ**. Наш план — взять именно это
(P0/P1 выше), оставаясь лёгким веб-инструментом с уникальными букетами и аналитикой рассадки.
Порядок работ и тикеты T1–T7 — в `docs/reference-analysis.md`; этот файл — обоснование «почему»
на примере SketchUp.
